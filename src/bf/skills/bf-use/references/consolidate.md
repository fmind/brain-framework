# Learn a reusable procedure

Use when several completed actions appear to teach the same reusable lesson. Search within the relevant project first; inspect a small set of outcomes, not all session transcripts. Read the expectations, actual results, circumstances and source refs.

Propose a concept or an update to the existing owning skill. State when it applies, the steps or decision rule, prerequisites, failure conditions, successful examples and counterexamples. Label a lesson from one event provisional. Repeated summaries of the same event are one source of support, not independent confirmation. Do not promote a claim merely because an agent repeated it.

Before promoting the procedure, try it on one relevant case not used to derive it, with a synthetic fixture or a user-authorized task. Record the result and limitations; do not mark OKF `verified` without a real check and verifier. If no held-out case is available, retain `status: draft` and the missing check. Failed cases should narrow or correct the procedure, not disappear from its provenance.

Extend the owning concept or skill before creating another. Keep the result brief and link to the original actions instead of copying their private inputs. Change reviewed knowledge through a diff; never rewrite collected records to support the lesson. Keep learning model-driven only in the user's agent host; deterministic routines can gather review candidates but do not perform this synthesis.
