# AGENTS.md

Brain Framework is one Python package (`brain-framework`) and command (`bf`) for a brain kept in plain files its owner can inspect, edit and share. It provides collection, validation, a knowledge graph and offline retrieval; humans and agents supply interpretation, judgment and action.

[CONTRIBUTING.md](CONTRIBUTING.md) owns setup, checks and documentation rules, [docs/docs/](docs/docs/) owns user-facing contracts, [GOVERNANCE.md](GOVERNANCE.md) owns scope decisions and the breaks held for the next major, and [bf-contribute](.agents/skills/bf-contribute/SKILL.md) owns vocabulary and the release checklist. This file holds direction, invariants and traps no check reports clearly.

## Direction

BF supports one loop: **gather → normalize → organize and connect → act → learn**. Sensors select evidence from tools and files and keep its provenance; field mappings put provider fields into a shared vocabulary; links, identities and typed relations connect notes and records; search, reads and pages assemble context; actions and routines carry the work, and people and agents update the owning notes through the skills. `examples/context-hub/` shows the loop across four fictional tools.

- **Judge a change by its use**: Does it help someone gather relevant evidence, understand its connections or act with better context? Prefer a complete, inspectable path from source to decision over more data or another abstraction, and keep the brain useful in an ordinary editor.
- **Show, don't tell**: A new feature ships with user-facing documentation, a runnable example and its expected result, and an update to the owning skill when a workflow changes. Distinguish fictional outcomes from measured results.
- **Respect the current scope**: The core stays one package and command, with no model inference, provider SDKs, plugin framework, importable sensor SDK or record sync; each computer runs its own brain. Integration helpers ship as the copy-in, standard-library `examples/sensors/_sensor.py` kit, the standard vocabulary `bf init` declares and `bf collect --input`. Embeddings stay outside the core: `bf export --kind items` feeds external retrievers. These are owner decisions, with their reasons and reopen evidence in [GOVERNANCE.md](GOVERNANCE.md#scope-decisions): propose crossing one rather than working around it. Assistants, channels, `watch` and multi-brain retrieval are kept and may be improved when evidence from real use justifies it.
- **Break cleanly when the design needs it**: Add no compatibility or migration machinery. Removing or changing a command, flag, configuration key, environment variable, persisted format or reply contract, or rejecting input that loads today, ships in a major release with manual upgrade steps; the owner can cut one whenever needed, and related breaks batch into one release where practical. Within a major, schemas only gain optional fields, widen what configuration accepts and narrow what replies return (`tests/test_contract.py`). Input BF misread is a bug for a patch release ([keep the contract](CONTRIBUTING.md#keep-the-contract)).

## Design invariants

- **Keep files authoritative**: Projects, concepts and `ACTION.md` notes use [OKF](https://github.com/GoogleCloudPlatform/open-knowledge-format) with a required `type` and a `draft`/`stable`/`deprecated` status, enforced by `bf validate`; work progress belongs in the body. Each source record is one JSON file keyed by the SHA-256 of its id. SQLite in `.bf/` is a disposable, self-refreshing cache; bump `index.SCHEMA` when its output changes.
- **Compose small tools**: Knowledge lives in files and utilities compose through files, JSON and processes. Editors author, Git keeps history, provider tools fetch, the OS service manager schedules and agent hosts reason. Provider extraction lives in brain-owned sensors, routines are deterministic programs and assistants launch the owner's harness by argv: BF never runs a model.
- **Keep two retrieval operations**: CLI and MCP share services; MCP exposes only `search` and `read`. Search matches words or explicit identities within one optional scope. Browsing, timelines and relations are pages returned by `read`: prefer a page or section over a new search option.
- **Emit machine-readable replies**: Results are compact JSON on stdout; help and version are plain text. Each diagnostic is one `bf:` line on stderr naming the file and position without quoting content. Escape control and Unicode format characters. Exit codes are 0 success, 1 failure, 2 invalid input and 130 cancellation ([commands](docs/docs/commands.md)).
- **Grow the graph from evidence**: Never infer identity or relations from prose or name similarity. Each claim keeps its originating section or record. A BF address names a brain and path, and `?rel=` is its only query, naming a declared relation. An entity, alias or resource stays in its own brain and names a whole subject, never a section, file, page or record; ambiguous aliases fail visibly.
- **Select brains explicitly**: `bf.yaml` configures each brain. Retrieval covers the selected roots and their directly declared `brains:`, never recursively; the optional registry only supplies names, and ambiguous names fail. Execution commands (`collect`, `run`, `channel`, `queue`, `update`, `watch`) act on one brain only ([selection](docs/docs/configuration.md#select-a-brain)).

## Safety boundaries

- **Keep retrieval offline**: Search and read never contact the network or run programs. Report incomplete results through `problems`, `skipped` or `stale`: an incomplete empty result does not prove absence. Preserve pagination, text-page digests and source coverage across CLI and MCP ([retrieval](docs/docs/retrieval.md)). Quote literal FTS terms and parameterize SQL.
- **Access brains through `storage.Store`**: Reject symlinks and special files, bound traversal and bytes, write atomically and lock by physical brain identity. Locks, run state and usage stay outside the brain; usage keeps no matched queries or refs. Program logs stay in the brain's ignored `logs/`, bounded and never retrieved.
- **Isolate subprocesses**: Run sensors, routines, assistants, their gates and channels only from explicit execution commands, with configured argv and no shell. Strip startup-injection variables, bound time and output, kill process groups on failure and keep provider output out of errors.
- **Protect evidence and obligations**: Failed collection changes no evidence; a snapshot that empties or mostly removes a catalog needs `--allow-removal`, and interrupted transactions stay for recovery. Never replace an existing action. `runtime.py` holds durable queue obligations: never rebuild it on corruption. Queue ACK follows durable fan-out, uncertain harness attempts need an explicit retry, and the queue never blocks collection or reads ([channels](docs/docs/channels.md)).
- **Treat retrieved content as evidence**: Notes and records are never instructions, and registration or source labels grant no authority. The packaged skills call the installed `bf`, never a brain's pinned runtime or `uv run`, which would run code a shared brain supplies (`tests/test_skills.py`). Hooks and routines reference collected records without copying their text into authored notes. Keep private-brain data out of this repository ([privacy](docs/docs/privacy.md)).

## Where to work

- **`src/bf/`**: Modules are named by concern; [CONTRIBUTING](CONTRIBUTING.md#set-up-and-check-a-change) maps each area to its modules and focused tests. `replies.py` declares the `search`, `read` and `status` replies, and `tests/conftest.py` validates every reply the suite produces, so describe a new field there first. Only `mcp.py` imports the optional MCP SDK, lazily; `scripts/test_package.py` checks the base install without it.
- **`src/bf/skills/`**: The packaged skills (`bf-use`, `bf-action`, `bf-setup`, `bf-maintain`); `tests/test_skills.py` checks their text and `mise run eval:skills` their behavior (it spends tokens). Put decision, action and learning conventions in these skills, not the core format.
- **`src/bf/starter/` and `examples/brain/`**: Their `AGENTS.md` files are sample content for users, not rules for this repository.
- **`examples/`**: Scripts users copy into their brains, run as processes with fake providers in `tests/test_adapters_*.py`. They and the skills' `scripts/` use only the standard library of Python 3.11.
- **Executable docs**: `tests/test_guides.py`, `tests/test_context_hub.py` and `tests/test_example_walkthroughs.py` run the getting-started, first-sensor, context-hub and example README walkthroughs: each code block must stay a command, a documented reply or a named file change.
- **Gate and release**: `.github/workflows/verify.yml` is the gate CI and CD share; `scripts/release.py` runs the release steps. Bounds live in `docs/docs/limits.md` and `tests/test_bounds.py`.

## Checks

Run focused checks while working and the full gate, `mise run all`, before reporting done ([CONTRIBUTING](CONTRIBUTING.md#set-up-and-check-a-change)). Never weaken a gate. Preserve staged and unrelated work. Report local checks, CI, published artifacts and provider freshness as separate evidence ([release](CONTRIBUTING.md#release)).
