# Examples

Start with the [four-tool walkthrough](context-hub/README.md): ingest fictional Workspace, Jira, GitHub, and Cloud records into `memories/<source>/*.json`, compile a Markdown project decision with `attr_list` metadata into `memories/projects/new-website.json`, query pure JSON records with `rg` and `jq` (`bf query`), and watch `bf review` flag `newer_evidence` when Jira changes. All runnable brains use local fixtures; no provider account, network call, or LLM is required.

| Question                                             | Example                                        | Observable result                                                                                                                                                                              |
| ---------------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Can I answer a question split across four tools?     | [Four-tool walkthrough](context-hub/README.md) | Four sensor records and one compiled project note share `memories/**/*.json`; `schemas/jira.json` enforces Jira fields; `bf review` flags `newer_evidence`.                                    |
| Can I author OKF notes, actions, jobs, and services? | [Example brain](brain/README.md)               | `attr_list` metadata compiles into `memories/{concepts,projects,actions}/*.json`; `routines/`, `services/`, `prompts/`, `services:`, `/bf` skill, `bf validate`, `bf eval`, and transfer pass. |
| How do I collect from live CLIs and agent logs?      | [Sensors](sensors/README.md)                   | Five Python 3.11+ stdlib adapters (`git`, `gh`, `gws`, local documents, agent telemetry) emit JSON records ready for `bf ingest SOURCE` or `bf.yaml` `jobs`.                                   |

From a repository checkout, run `uv sync --locked` first, then follow each README's disposable-copy instructions so ingestion and edits stay outside the checked-in fixtures. The test suite (`tests/test_examples.py`) runs these examples and every sensor adapter (including provider failures) on temporary copies.
