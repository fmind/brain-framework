# Examples

Start with the [four-tool walkthrough](context-hub/README.md): ingest fictional Workspace, Jira, GitHub, and Cloud records into `memories/<source>.jsonl`, compile a Markdown project decision with `attr_list` metadata into `memories/projects.jsonl`, query flat JSONL records with `rg` and `jq` (`bf query`), and watch `bf review` flag `newer_evidence` when Jira changes. All runnable brains use local fixtures; no provider account, network call, or LLM is required.

| Question                                         | Example                                        | Observable result                                                                                                                                                                  |
| ------------------------------------------------ | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Can I answer a question split across four tools? | [Four-tool walkthrough](context-hub/README.md) | Four sensor sources and one compiled project note share `memories/*.jsonl`; required `schemas/*.json` enforce fields; `bf review` flags `newer_evidence`; `evals/smoke.py` passes. |
| Can I author notes, bundles, and loops?          | [Example brain](brain/README.md)               | `attr_list` metadata compiles into `memories/{concepts,projects,actions}.jsonl`; `sensors/`, `routines/`, `prompts/`, `loops:` (cycle + `when: daemon`), `bf check`, and transfer. |
| How do I collect from live CLIs and agent logs?  | [Sensors](sensors/README.md)                   | Five Python 3.11+ stdlib adapters (`git`, `gh`, `gws`, local documents, agent telemetry) emit JSON records ready for `bf ingest SOURCE` or `bf.yaml` `loops:`.                     |

From a repository checkout, run `uv sync --locked` first, then follow each README's disposable-copy instructions so ingestion and edits stay outside the checked-in fixtures. The test suite (`tests/test_examples.py`) runs these examples and every sensor adapter (including provider failures) on temporary copies.
