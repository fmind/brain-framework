# Examples

Start with the [four-tool walkthrough](context-hub/README.md): ingest fictional Workspace, Jira, GitHub, and Cloud records into `memories/<source>.jsonl`, compile a Markdown project decision with `attr_list` metadata into `memories/_notes.jsonl`, search ranked BM25 results with `bf query` (or directly via `rg`/`jq`/`duckdb`), and watch `bf review` flag `newer_evidence` when Jira changes. All runnable brains use local fixtures; no provider account, network call, or LLM is required.

| Question                                         | Example                                        | Observable result                                                                                                                                                                               |
| ------------------------------------------------ | ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Can I answer a question split across four tools? | [Four-tool walkthrough](context-hub/README.md) | Four sensor sources and compiled `memories/_notes.jsonl` share `memories/`; optional `schemas/*.json` enforce domain fields; `bf review` flags `newer_evidence`; `evals/smoke.py` passes.       |
| Can I author notes, bundles, and loops?          | [Example brain](brain/README.md)               | `attr_list` metadata compiles into `memories/_notes.jsonl`; telemetry uses `ingest.schema: usages`; `sensors/`, `routines/`, `agents/`, `prompts/`, `loops:`, `bf check`, and transfer all run. |
| How do I collect from live CLIs and agent logs?  | [Sensors](sensors/README.md)                   | Five Python 3.12+ stdlib adapters (`git`, `gh`, `gws`, local documents, agent telemetry) emit JSON records ready for `bf ingest SOURCE` or `bf.yaml` `loops:`.                                  |

From a repository checkout, run `uv sync --locked` first, then follow each README's disposable-copy instructions so ingestion and edits stay outside the checked-in fixtures. The test suite (`tests/test_examples.py`) runs these examples and every sensor adapter (including provider failures) on temporary copies.
